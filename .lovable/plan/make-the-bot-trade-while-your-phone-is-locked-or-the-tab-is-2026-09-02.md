# Make the bot trade while your phone is locked or the tab is closed

## Short answer
Not today. The bot currently lives in the browser. When you lock your phone or put the browser tab in the background, iOS/Android throttle JavaScript timers and usually disconnect WebSockets, so signals stop firing and orders cannot be submitted. The only reliable way to trade while away is to move the decision engine and order placement to the server.

## Non-negotiable: nothing about your current trading changes
- The client-side bot, signals, thresholds, EV margin, and order flow stay exactly as they are.
- No changes to `computeSignals`, `placeOrder`, or the paper/live switches you already use.
- The new server bot is **off by default** and only runs if you explicitly enable it.
- Your existing “doing gigs right now” setup keeps working in the foreground exactly as it does now.

## Goal
Add an optional server-side runner that can trade even when your phone screen is off, controlled by saved settings, while leaving the current dashboard bot untouched.

## What will change (all additive)
1. A new `bot_settings` table stores your per-user preferences: mode (paper/live), bet size, EV margin, max trades per candle, and an on/off switch.
2. A server-side loop polls Coinbase/Binance REST and Kalshi order books every few seconds.
3. The existing `computeSignals` logic is reused server-side to score each pair.
4. When enabled, the server places orders directly through Kalshi for the top 1–2 signals per candle.
5. All server actions are recorded in the existing `signal_log` and `trade_log` tables.
6. The dashboard becomes a monitor and kill switch: you can see status, last server check, P&L, and disable the server bot instantly.

## Implementation steps

```text
User settings (DB)          Server scheduler           Kalshi / feeds
       │                           │                           │
       ▼                           ▼                           ▼
 bot_settings ──────►  server bot loop  ◄─────── market_snapshots
 (mode, bet, EV,
  enabled)               computeSignals
                              │
                              ▼
                      placeOrder server-side
                              │
                              ▼
                        trade_log / signal_log
                              │
                              ▼
                    Dashboard status + kill switch
```

### 1. Settings persistence
- Create `bot_settings` table with columns: `user_id`, `enabled`, `server_enabled`, `mode`, `bet_size`, `ev_margin`, `max_trades_per_candle`, `updated_at`.
- Add RLS policies so a user can only read/update their own row.
- Add a server function to read/write settings, used by the dashboard.

### 2. Server-side data collector
- Build a reusable server module that fetches BRTI spot from Coinbase/Binance REST every 1–2 seconds and Kalshi market snapshots every 3–5 seconds.
- Write the snapshots into `market_snapshots` so the replay/tuning pipeline keeps working.
- Maintain an in-memory rolling tick window for each pair (or reuse the last N snapshots).

### 3. Server-side signal engine
- Extract the pure scoring math from `computeSignals` into a shared function that works with both browser state and server-fetched data.
- Run the scoring inside an authenticated server function or scheduled route at ~15-second cadence during each 15-minute candle's trade window.
- Respect the saved `ev_margin`, `bet_size`, and `max_trades_per_candle`.

### 4. Server-side execution
- Add a protected server function that, when `mode === "live"` and credentials are configured, calls the existing `placeLiveOrder` path.
- For `mode === "paper"`, simulate the fill using the current Kalshi midpoint and record it.
- Track placed trades per candle server-side to avoid over-trading.

### 5. Scheduling
- Add a new `/api/public/bot-tick` route protected by `LOVABLE_CRON_SECRET`.
- Configure `pg_cron` to call it every 15 seconds during market hours, or use a 1-minute cron and have the tick evaluate the current candle.
- Make the tick idempotent: record already-processed candles/slots to prevent duplicate orders.

### 6. Dashboard updates
- Add a "Run on server" card to `EnginePanel` or `Dashboard` with:
  - toggle to enable/disable server bot,
  - display of last server tick time,
  - current saved mode/bet/EV,
  - a big "STOP SERVER BOT" button.
- Keep the existing client-side paper/live toggles for users who still want to trade only while the app is open.

### 7. Safety defaults
- Server bot defaults to **off**.
- When first enabled, it runs in **paper mode** for at least 24 hours before the user can flip it to live.
- Live server trading requires an explicit second confirmation and a separate `server_live_enabled` flag.
- All server orders still honor the same gates: 86% confidence, EV margin, spread, skew, sigma cushion.

### 8. Testing
- Verify paper trades are generated by the server with the screen locked (simulate by closing the preview tab).
- Confirm live orders are only submitted when the server live flag and Kalshi credentials are both present.
- Check that disabling the server bot from the dashboard stops new orders within one tick.

## Out of scope for this plan
- Push notifications (can be added later once server trading is stable).
- Replacing the existing client-side bot; this plan keeps both side by side.

## Risks
- Server bugs can place real money orders while you sleep. The paper-first default and separate live flag mitigate this.
- Kalshi rate limits: server polling must stay within Kalshi's limits; use cached snapshots and retry with backoff.
